# AGENTS.md

Entry point for AI coding agents other than Claude Code (Codex, Grok, …). Claude Code reads `CLAUDE.md`; this file points every other agent at the same rules. Keep it short — details live in the files below.

## Read first, in this order
1. `HANDOFF.md` — ownership (development vs production track), the task plan, the quick start.
2. `CLAUDE.md` — project rules, commands, architecture, gotchas. Every rule there applies to you; only the hook and subagent mechanics are Claude Code-specific (see below).
3. `.ai/memory/current-state.md`, `.ai/memory/known-issues.md`, `.ai/memory/session-handoff.md` — the state left by the last session.
4. The latest phase report in `docs/ai/reports/` and the ADR index `docs/architecture/decisions/README.md`.

Nested instructions apply to their directory and are **not** loaded automatically from the root — read the one for every file you change: `backend/AGENTS.md` (Laravel Boost guidelines, generated) and `frontend/<app>/AGENTS.md` (Next.js 16 — read `node_modules/next/dist/docs/` before writing Next code).

## Hard rules
Claude Code enforces these with hooks and permission lists (`.claude/settings.json`, `.ai/hooks/`); in your agent nothing enforces them, so you do.
- Reference codebases are read-only: `app.uz`, `telegram.uz`, `datahub.uz`, `geo.uz` and the nginx mirrors (paths in `.ai/local.env`). No writes, no project tooling, no folder copies there; never open their `.env*`, `envprod*` or `key.md`.
- The kvadro² → HOMI migration is planned in `docs/migration/` (conventions in its `README.md`). Wave 1 is worked from the single queue `docs/migration/wave-1/README.md`: take the first package that is not `DONE` and read its specification. The legacy checkout (`KVADRO_ROOT` in `.ai/local.env`) is read-only: no edits, no builds, no `npm`, no dev server there, and no copy of its code.
- Never read, print or copy secrets: `.env*` except `*.example`, private keys (`*.key`, `*-key.pem`), `key.md`, `.claude/settings.local.json`. List key names with `grep -o '^[A-Z_]*=' backend/.env`.
- No machine-specific absolute paths in tracked files — they belong in `.ai/local.env`.
- Never `php artisan serve` (ports 8000/8001 are taken); never `brew services start|restart nginx` (KI-13) — use `make dev-nginx`.
- "The developer" is the person running you. Dependency changes, new tools and anything on staging/production also need the first developer's OK (the **gate** column in `HANDOFF.md` §4). Never run sudo yourself — the developer runs those steps in a terminal.
- Ask the developer first: sudo, force-push, `reset --hard`, `clean`, deleting branches, `migrate:fresh|reset|rollback`, `db:wipe`, any dependency change (`composer require|remove|update`, `pnpm|npm add|remove|update`), killing processes, ssh/scp/rsync/psql, anything that touches staging, production, bots or buckets.
- Never push to `main`: branch + PR, Conventional Commits in English (ADR-0010, `docs/handoff/parallel-work.md`).
- Never edit generated files: `backend/AGENTS.md`, `.claude/skills/**`, `.agents/skills/**`, `.grok/skills/**`, `backend/resources/js/{actions,routes,wayfinder}/**`, `docs/backend/package-registry.md`, `.ai/memory/package-capabilities.md`.
- After editing PHP run `vendor/bin/pint --dirty --format agent` in `backend/`; after editing JS/TS in a Next app run `pnpm exec eslint --fix <file>` in that app.
- Never claim a check you did not run — show the command and its output (mandate rule 7).
- Talk to the developer in their language (Russian so far); repository artifacts are in English.

## Tooling for this agent
- Skills: `.agents/skills/` (generated by `make ai-sync` from `.ai/skills/` plus the official Boost skills). Run the `save-session` skill before a session ends.
- Domain checklists: `.ai/agents/*.md` are Claude Code subagent definitions — read the matching one before working in its area (Telegram bot, intake, listing matching, PostgreSQL/PostGIS, security review, reference-codebase reading).
- Laravel Boost MCP (`search-docs`, `database-schema`, …): set it up as in `docs/handoff/environment.md` §4; use `search-docs` before relying on version-specific Laravel APIs. Do not use its `record-rule` tool yet (`.ai/rules` is not approved).
- Before finishing a task: `make ci-backend` and/or `make ci-frontend` for the side you touched; `make ai-hooks-test` if `.ai/hooks/` changed.
