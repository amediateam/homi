# 07 — Business rules (compiled)

Every business rule `BR-…` found by the wave-1 audits, grouped by domain, with its status, its source line and the
features of [09](09-feature-parity-matrix.md) that implement it. The rule text is quoted from the owning audit document and
only tightened (sub-bullets joined, markdown removed; three rules that contained tables are rewritten as one sentence with the
same content). The owning document stays the source of truth; when this file and the source disagree, the source wins and
this file is corrected.

Status: **compiled 2026-11-09** from `02` (BR-API), `03` (BR-APP), `04` (BR-BOT), `03b` (BR-LND, BR-SEO) and `06` (BR-DATA).
Changes to these rules are deviations (`DEV-…`, `09` §4) and stay `PROPOSED` until the developer approves them.

The ID cell links to the owning document (this file only references the rules; `collect_ids.py` keeps them defined there).
Columns: **Status** — as recorded at the source (qualifiers kept, e.g. "CONFIRMED (client) / DOCUMENTED_ONLY (server)"; counts
use the weakest). **Source** — `doc:line` of the definition. **Features** — implementing features, primary first (the primary
feature also decides the domain). **Flags** — `C-NN` = the rule takes part in a contradiction (§3); `DEV-NNN` = a proposed
deviation changes the rule; `= BR-…` = the rule restates or depends on the named rule.

Domains follow the requested grouping, with access extended by the API contract (errors, pagination, timeouts) and
settings, and listings extended by contact, sharing and personal lists. The data-model rules of `06` (`BR-DATA-…`) are all
listed under the data domain even where they restate a rule of another domain; the `= BR-…` flag points at the original.
